## 为什么值得做

**你的经历是资料库里最缺的那部分。**

上游资料里很多内容来自走过同样路的人：

- 某家医院最近的实际要求是什么
- 哪个窗口对这类业务熟悉
- 某个医生的接诊政策变了
- 某种药在本地能不能开到

**这些信息只有刚经历过的人知道。** 而它们对后面的人价值极高。

## 比自建平行资料库更有用

**建一个平行资料库的问题是：**

1. 会漂移 —— 上游更新了，副本不会跟着更新
2. 分散贡献 —— 同样的事被做两遍
3. 无人校对 —— 副本没有社群纠错机制

**往上游提一条修正，能影响所有看那份资料的人。**

## 可以贡献什么

| 类型 | 例子 |
| --- | --- |
| 更新过时信息 | 医院政策变了、医生停诊了 |
| 补充缺失内容 | 某个城市还没有条目 |
| 修正错误 | 数字、流程、表述有误 |
| 翻译 | 英文资料的中文译文 |
| 校对 | 检查现有条目的准确性 |

## 怎么开始

**上游有完整的[贡献者指南](https://mtf.wiki/zh-cn/docs/contributor-guide)，从那里开始。**

内容源码在 GitHub 上：[project-trans/MtF-wiki](https://github.com/project-trans/MtF-wiki)。基本流程和给任何开源项目提 PR 一样：

1. 找到需要修改的页面（页面底部通常有「在 GitHub 上编辑」的链接）
2. 提出修改
3. 说明修改依据
4. 等待审核

**不需要是程序员。** 改 Markdown 文本就够了。

## 不熟悉 Git 怎么办

- **先提 issue** —— 说明哪一页有什么问题、依据是什么。维护者会处理。
- **联系维护者** —— 上游页面有联系方式。
- **找社群里的朋友帮忙** —— 很多人愿意代提。

**提供信息本身就是贡献**，格式问题可以交给别人。

## 关于「我的经验值得写吗」

**值得。** 判断标准很简单：

- 是不是你亲身经历的？
- 是不是具体、可核实的？
- 是不是对别人有用？

**不要写：** 未经核实的传闻、对个人的评价、带商业动机的推荐。

## 本站与上游的关系

**本站是索引层，不是替代品。** 如果你在本站发现某条内容有价值，更好的做法是把它贡献给上游，而不是留在这里。

**本站的内容随时可能过时，上游有社群持续校对。**
